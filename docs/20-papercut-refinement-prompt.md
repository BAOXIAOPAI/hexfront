本轮只修改 design/desktop 内的独立原型及相关交付说明，不改 apps/、packages/、正式协议/规则，不部署、不另建项目、不重选视觉方向。开始前检查 git status，保护现有未提交文件。

最重要的改动是交易：玩家先在外部语音谈好，网页用于执行。将当前密集的双栏加减表单改为两步图形化选择：
1. 我想收到：五种资源图标、名称、醒目整数数量和滑条。
2. 我愿给出：同样方式，按自己持有资源限制给出数量。
顶部始终显示交易对象；第二步保留第一步摘要和修改入口，底部显示完整收付条件后直接发送，不再叠第三层确认。
滑条保留点按加减/键盘精确调整能力，不新增任意资源数量上限，不泄漏对方资源种类。允许任意一侧为零的赠予/索取，禁止双方全零。
提供“发起交易/收到的提议（N）”切换，新报价不抢焦点，切换不丢草稿。保持 10 秒有效、3 秒冷却、每人一条、多条并存等既有规则。

同步改善小字和低对比度、按钮主次、弃牌“持有/已选”的表达、黄色道路与地形的区分，减少常驻教程和技术说明。保留现在的纸雕海岛风格。

动效先用现有 CSS/SVG/轻量浏览器动画实现：按钮和选牌反馈、交易步骤切换、短骰子翻滚，以及一种抽发展卡效果。不要上 3D/物理引擎。动画只表现结果，不决定结果；不能延迟报价过期、弃牌锁或其他逻辑更新；支持减少动态模式和失败反馈。抽卡不是新增“交易卡”玩法。

先简述设计调整与改动范围，再完成原型。验证 1280×720 和 1440×900，测试返回编辑、混合资源、赠予、数量边界、报价切换和动效降级。交付运行预览、关键截图、改动说明、测试记录，更新状态页和设计规范。明确哪些仍是本地模拟，不宣称正式游戏已接入。遇到真实规则冲突再提问，普通设计细节按任务书自行推进。
