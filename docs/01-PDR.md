# PDR · 卡坦岛线上桌游

> **PDR** = Product Design Requirements（产品设计需求）
> 版本 **v0.2** · 2026-11-05
> 状态：**定位已修正，等待变体规则确认**
>
> 本文档只定"要做成什么样"，不涉及具体代码。开放问题见 `05-decisions.md`。
> **规则以 `06-variant-rules.md` 为准**，`02-rules-spec.md` 仅作官方基线参照。

---

## 1. 一句话定义

一个**支持"信任玩法"的卡坦变体**：规则骨架来自卡坦岛，但核心机制是存牌、借港、口头支票——**这三样在官方规则下一个都不存在**。

---

## 2. 问题陈述

### 2.1 真正的空白不是"快"，是"装不下你们的玩法"

v0.1 的判断是「现有线上平台交易太慢」。这个判断只是表层。

经过你的说明，真正的问题是：

> **现有平台实现的是「官方规则的数字化」，而你们玩的不是官方规则。**

你们的玩法里有一整套官方规则没有的机制：

| 你们的机制 | 官方规则 | 现有平台能否支持 |
|---|---|---|
| 掷骰前存牌，规避 7 的风险 | 掷骰前不可交易 | ❌ |
| 借用他人港口 | 港口仅所有者可用 | ❌ |
| 任意玩家向当前玩家发起交易 | 仅当前玩家可发起 | ❌ |
| 口头支票，允许毁约 | 规则未涉及 | ❌（也不该支持） |
| 银行无限资源 | 每种 19 张 | ❌ |

**这才是真正的空白。** colonist.io 不是做得不够好，是它在规则层面就装不下这套玩法——它忠实实现了官方规则，而你们玩的不是官方规则。

### 2.2 所以为什么还要自己做

三个理由，按重要性排序：

1. **现有平台无法支持这套变体**（根本原因，且无法绕过）
2. **语音谈判时，网站只需要"执行与记账"**——而现有平台的交易 UI 过重，反而碍事
3. **你想做**（正当理由，不需要辩解）

---

## 3. 目标用户与阶段

### 阶段一：朋友局（v0.1）
- **用户**：作者本人 + 3~5 位固定牌友
- **特征**：资深玩家，懂全部规则，**不需要教程、不需要提示、不需要防呆**
- **准入**：房间号 + 昵称，**没有账号系统**
- **规模**：同时 1~2 桌
- **核心诉求**：快、顺、不打断
- **谈判方式**：外部语音（微信/腾讯会议），系统不提供

### 阶段二：公开（v0.2+）
- **用户**：对现有平台交易体验不满的玩家
- **新增需求**：账号、匹配、评分、掉线托管、防作弊、旁观
- **明确不是现在的目标**，但阶段一的架构不能堵死阶段二的路

## 4. 设计原则（冲突时的裁决依据）

这五条是后续所有争议的判据，优先级从上到下：

**P1 · 规则以文档为准，不擅自优化**
所有规则以 `06-variant-rules.md` 为准；06 未覆盖的，按 `02-rules-spec.md` 的官方基线执行。
凡文档写明的，不得在实现时因"这样更简单/更符合官方/更合理"而擅自改动。规则歧义处一律登记待裁决，不擅自决定。

**P2 · 速度优先于表演**
从掷骰到资源入账 ≤ 2 秒。禁止无法跳过的动画。任何"演出"必须可被点击略过。

**P3 · 语音谈判，网站执行**
谈判发生在语音里，系统只负责把谈成的事快速、准确地执行。
**任何妄图"替代语音"的 UI 都是错的**——不要做竞价看板、不要做议价助手、不要做站内聊天。交易界面越简越好，目标是把语音里的一句话变成屏幕上的两次点击。

**P4 · 信息克制**
只呈现实体桌上能获得的信息。不提供资源构成推算、不提供胜率预测、不提供最优解提示。
> ⚠️ 这条是设计哲学分歧点，见 **D-02**。若你要"辅助模式"，我们需要讨论它是否默认关闭。

**P5 · 断线无感**
手机锁屏、切后台、来电话、地铁进隧道——回来时必须原地复原，且不占用手牌信息、不丢操作。

## 5. 范围界定

### 5.1 v0.1 必做（朋友局可完整打完一局）

| 模块 | 内容 |
|---|---|
| 房间 | 建房、房间号加入、昵称、4 人满员开局、房主可踢人 |
| 开局摆位 | 蛇形 1-2-3-4-4-3-2-1，校验距离规则，第二轮立即产资源；**总时长限 3 分钟** |
| 回合循环 | **单一行动阶段，动作顺序完全自由**；掷骰必须发生，但位置不限 |
| 资源 | 5 种资源、**银行无限** |
| 交易 | 以当前玩家为中心的请求/审批；**任意玩家可向当前玩家发起**；支持**零对价**（存牌） |
| 借港 | **非所有者可借用当前玩家港口**，由当前玩家代执行兑换 |
| 建造 | 路 15 / 村 5 / 城 4，合法性校验，资源扣减 |
| 发展卡 | 25 张牌堆、购买、骑士/垄断/丰饶/筑路/胜利点、每回合限打 1 张 |
| 争夺 | 最长路（5 条连续）、最大军（3 骑士），动态得失 |
| 强盗 | 掷 7 弃牌、移动、抽牌 |
| 存牌提示 | 手牌 ≥8 时实时显示"掷出 7 需弃 N 张"，随交易即时更新 |
| 结束 | 回合达 10 分立即获胜，结算页 |
| 连接 | WebSocket 实时同步、断线重连、状态恢复 |
| 基础统计 | 每个玩家的资源数、发展卡数、已建数量、分数构成 |

> ⚠️ 加粗项是与 v0.1 初稿的差异，全部来自变体规则（`06-variant-rules.md`）。

### 5.2 v0.2 才做（公开化）
账号体系 · 匹配 · Elo 评分 · 旁观 · 对局回放 · 掉线托管/超时跳过 · 举报 · 多语言

### 5.3 明确不做（本项目永久排除）

| 排除项 | 理由 |
|---|---|
| **站内语音** | 你说麻烦，且移动端体验差；用外部语音（微信/腾讯会议） |
| **口头支票 / 债务系统 / 借条** | **这是核心决定**：系统记录一个无法强制执行的承诺，是假保障。信任必须留在语音里，见 `06` 第 6 节 |
| 海洋扩展、城市与骑士等所有扩展 | 基础版尚未打磨完，扩展会稀释重点 |
| AI 对手 | 卡坦的 AI 本质是议价 AI，独立课题，单独立项 |
| 原生 App（iOS/Android） | PWA 已满足需求，且绕开商店审核 |
| 微信小程序 | **游戏类小程序上线需版号，个人开发者无法取得，硬门槛** |
| 任何形式的商业化（收费/广告/赞助） | 见版权说明。免费是当前法律安全区的前提 |

## 6. 功能需求

编号供讨论引用。**P0 = v0.1 必须，P1 = v0.1 尽量，P2 = v0.2**。

### 6.1 房间与开局

- **FR-01 (P0)** 创建房间：生成 6 位房间号，房主设定昵称
- **FR-02 (P0)** 加入房间：输入房间号 + 昵称，重名时提示
- **FR-03 (P0)** 准备状态：全员准备后房主手动开局（不做自动倒计时）
- **FR-04 (P0)** 房间内可查看本局地图与宝石分配（开局前预览）

### 6.2 开局摆位

- **FR-10 (P0)** 严格蛇形顺序：玩家 A→B→C→D→D→C→B→A
- **FR-11 (P0)** 合法性校验：与所有已有村庄/城市至少相隔一个交叉点（距离规则）
- **FR-12 (P0)** 第二轮放置时，村庄必须紧邻刚放下的道路端点
- **FR-13 (P0)** 第二轮放置完成后，立即结算该村庄相邻地块的资源（每块 1 张）
- **FR-14 (P1)** 显示"该位置可产出哪几种资源"的静态信息（不显示概率加权评分）
- **FR-15 (P0)** **选地总时长 3 分钟**，服务端权威计时，最后 60 秒变色提示
- **FR-16 (P0)** 超时按两级处理：先降为每人每次 15 秒，再超时由系统自动放置（待 Q-04 确认）

### 6.3 回合与产出

- **FR-20 (P0)** 回合状态机：`TURN_START → 行动阶段 → TURN_END`，**唯一硬约束是未掷骰不得结束回合**
- **FR-20b (P0)** **动作顺序完全自由**：交易、借港、建造、打发展卡、掷骰，任意顺序、任意次数（发展卡除外）
- **FR-20c (P0)** 掷骰必须发生一次，且一回合仅一次；掷骰后仍可继续交易与建造
- **FR-20d (P0)** 「当回合购买的发展卡不能当回合打出」仍然有效
- **FR-21 (P0)** 掷骰：两组骰子，2~12，含概率权重
- **FR-22 (P0)** 非 7 结算：所有与该数字相邻且有建筑的玩家按"村庄 1 / 城市 2"获取
- **FR-23 (P0)** 银行无限资源，不存在库存不足
- **FR-24 (P0)** 掷 7：①所有手牌 ≥8 的玩家同时弃一半（**向上取整**，由玩家**自选弃哪些牌**）②掷骰者移动强盗 ③可抽取相邻玩家 1 张随机手牌
- **FR-25 (P0)** 弃牌阶段为"同时选择、同时揭示"，不暴露弃牌者的选择过程
- **FR-26 (P0)** 强盗所在地块不产资源；强盗可放在任意地块（含沙漠、含自己建筑旁）
- **FR-27 (P0)** 结束回合：仅掷骰后阶段可执行，交接给下一位
- **FR-28 (P1)** 回合操作日志（可折叠，含"谁在何时做了什么"）

### 6.4 交易（本项目核心，详见 `03-trade-and-ux.md`）

- **FR-30 (P0)** 玩家间交易：任意比例、任意种类、任意方向（含**以少换多**）
- **FR-31 (P0)** 定向交易：当前玩家指定对象 → 填给/要 → 发送 → 对方接受
- **FR-32 (P0)** 请求交易：**任意非当前玩家**可向当前玩家发起请求（V-3）
- **FR-33 (P0)** 请求列表：当前玩家在一个面板内看到全部待处理请求，逐个接受/还价/拒绝
- **FR-34 (P0)** 还价：接收方可修改条件回推，只保留最新一层（不做分支树）
- **FR-35 (P0)** **零对价转移**：交易任一方可给 0 张（存牌的前提，见 Q-07）
- **FR-36 (P0)** 交易达成后立即原子性转移，不可撤销、不可回滚
- **FR-37 (P0)** 银行/港口交易：4:1 无港、3:1 通用港、2:1 专用港
- **FR-38 (P0)** **借港代换**：当前玩家可替他人执行港口兑换，资源从该他人账户扣、产物进其账户
- **FR-39 (P0)** 成交公示："A 用 X 换了 B 的 Y"，1.5 秒淡出
- **FR-39b (P0)** **存牌风险提示**：手牌 ≥8 时显示"掷出 7 需弃 N 张"，随交易实时更新
- **FR-39c (P1)** 「代管」界面标记：显示手中有几张是代他人保管（纯界面，不记录债权）

### 6.5 建造

- **FR-40 (P0)** 道路：木+砖，必须沿边、必须连通自己已有路/村/城
- **FR-41 (P0)** 村庄：木+砖+羊+麦，必须满足距离规则，必须连通自己的路
- **FR-42 (P0)** 城市：3 矿+2 麦，只能升级自己的村庄
- **FR-43 (P0)** 数量上限：路 15、村 5、城 4，用尽后不可再建
- **FR-44 (P0)** 建造扣资源与放置为同一原子操作，不存在"扣了资源没放下"
- **FR-45 (P1)** 建造预览：选中位置时高亮显示合法性（绿/红），不显示"推荐"

### 6.6 发展卡

- **FR-50 (P0)** 购买：羊+麦+矿，从牌堆顶抽 1 张，**同回合可购买多张**（若资源足够）
- **FR-51 (P0)** **每回合只能打出 1 张**非胜利点发展卡
- **FR-52 (P0)** **当回合购入的卡不可当回合打出**（含骑士），下回合起可用
- **FR-53 (P0)** 胜利点卡：抽到即计 1 分，保留在手中不公示，**不占用"每回合 1 张"额度**
- **FR-54 (P0)** 牌堆 25 张，抽完不补充、不洗牌
- **FR-55 (P0)** 骑士：移动强盗 + 可抽牌，同时计入最大军
- **FR-56 (P0)** 垄断：选定一种资源，其余所有玩家该资源**全部**交出
- **FR-57 (P0)** 丰饶：从银行取任意 2 张资源（可同种，受银行存量限制）
- **FR-58 (P0)** 筑路：免费放置 2 条路，可不放满 2 条，多余不返还

### 6.7 争夺与胜负

- **FR-60 (P0)** 最长路：连续 ≥5 条得 2 分；同长度时先达成者持有；被截断后若不足 5 条则立即失去
- **FR-61 (P0)** 最大军：首个打出 3 张骑士得 2 分；后续需**严格多于**当前持有者才夺取
- **FR-62 (P0)** 胜负：任意时点分数 ≥10 立即结束（含刚打出胜利点卡的瞬间）

### 6.8 连接与恢复

- **FR-70 (P0)** 断线后重连，恢复到**完全相同的局面**（含未完成的交易提案）
- **FR-71 (P0)** 断线期间回合计时暂停（若启用计时，见 D-05）
- **FR-72 (P0)** 同一账号/昵称重复登录时，踢掉旧连接（防双开作弊）

### 6.9 展示

- **FR-80 (P0)** 六边形棋盘，SVG 渲染，19 格标准布局
- **FR-81 (P0)** 每位玩家可见：自己的全部手牌、他人的手牌**数量**
- **FR-81b (P0)** **他人手牌 ≥8 时给予醒目警示**（红描边等）——这是「恶意投 7」的决策依据，实体桌上本来就看得见，见 `06` 第 3.3 节
- **FR-82 (P0)** 公开信息：各玩家已建路/村/城数量、已打出发展卡数量、持有港口、当前分数构成
- **FR-83 (P0)** **不显示**他人的资源构成，也不显示任何推算结果
- **FR-84 (P1)** 分数构成可展开（基础建筑 x 分 + 最长路 + 最大军 + 胜利点卡）

## 7. 非功能需求

| 项 | 要求 |
|---|---|
| 平台 | 移动端优先的 Web；可添加到主屏幕（PWA），全屏无地址栏 |
| 兼容 | iOS Safari 16+、Android Chrome 110+、桌面 Chrome/Edge/Safari 最新版 |
| 首屏 | 冷启动到可操作 < 2s（4G） |
| 同步延迟 | 同区域 < 300ms 端到端 |
| 权威性 | **服务端权威**：客户端任何状态变更必须经服务端裁决，客户端不得自行推进状态 |
| 可恢复 | 任意时刻刷新页面/杀进程，重新进入即回到当前局面，零信息损失 |
| 可测试 | 规则引擎为纯函数、零 I/O 依赖、单元测试覆盖全部规则条目 |
| 数据 | 每局完整事件日志落盘，可离线重放（调试与复盘依据） |
| 无障碍 | 色盲友好：资源不仅靠颜色区分，同时用图形/文字标识 |

## 9. 里程碑

每个里程碑**必须验收通过才进入下一个**，不做并行推进。

| 里程碑 | 交付物 | 验收标准 |
|---|---|---|
| **M0 文档** | 本套 5 份文档 | 所有 D-xx 决策项关闭 |
| **M1 规则引擎** | 纯 TS 包，无 UI | 100% 规则条目有单测；能脚本化跑完一整局并输出终局分数 |
| **M2 本地热座** | 单机可玩 UI | 一台设备上 4 人轮流操作，完整打完一局无异常 |
| **M3 联机骨架** | 房间 + WebSocket 同步 | 4 台设备同局，任意时刻刷新不丢状态 |
| **M4 交易系统** | 请求/审批 + 零对价 + 借港 | 真实朋友局完整打完，交易路径全部走通 |
| **M5 朋友局上线** | 部署 + PWA | 手机添加到主屏幕可玩，实战 ≥3 局 |
| **M6 公开化** | 账号/匹配/评分 | 另立文档 |

**M1 先于 UI 是本方案最重要的顺序决策**：规则引擎没有 UI 也能被完整测试，而 UI 一旦先于引擎成型，规则缺陷会以"看起来能玩"的形式藏起来，后期改动成本翻倍。

## 10. 成功判据（v0.1）

1. 四位朋友不用任何讲解，只凭房间号就能完整打完一局
2. 单回合（掷骰到结束）平均耗时不超过实体桌的 1.2 倍
3. 一局中因界面问题产生的误操作 ≤ 1 次
4. 全程无掉线导致的对局中断
5. **最关键的一条**：朋友愿意主动再开第二局
