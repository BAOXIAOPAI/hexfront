## 3. 相机、手势与热区（指南 5）

**关键实现选择：相机作用在 SVG 的 `viewBox` 上，不往 SVG 里塞 `<g transform>`。**

推导（已由 `phase-d.test.ts` 单测覆盖）：
```
s   = min(W/box.width, H/box.height) × zoom
screen = (world − boxCenter) × s + viewportCenter + pan
```
`zoom=1 / pan=0` 时得到的 viewBox 与 `scene.ts` 原始包围盒同心且地图完整可见，因此不改变原有观感。缩放围绕手势中心：先反解该点世界坐标，再用 `panForZoomAround()` 反推新平移量，保证该点不动。

| 指南条目 | 落地 |
|---|---|
| 5.1 独立相机、STATE 不重置 | 相机状态只存在 `BoardCamera` 实例里；`render()` 后 `camera.setScene()` 只改 viewBox，不重置 zoom/pan |
| 5.1 单指平移 / 双指缩放 / 桌面拖动与按钮 | Pointer Events + `wheel`；`+ / − / ⌂` 按钮；缩放范围 1–3.2 |
| 5.1 pointercancel / 多指 / 抬起 / 失焦 / 旋转 | 均有处理；`resize`/`orientationchange` 只重算可视区域，不丢选择 |
| 5.1 touch-action | 仅 `.board-stage` 与 SVG 设 `none`，抽屉/行动区保留 `pan-y` |
| 5.1 拖动阈值 | 8 CSS px；超阈值的 click 在捕获阶段被吃掉，绝不触发建造 |
| 5.2 热区用屏幕坐标 | `cameraCandidates()` 由真实 `Geometry` 生成合法路口/边/地块，`nearest()` 按 `worldToScreen` 后的实际屏幕距离取最近；不靠放大的透明圆 |
| 5.2 歧义消歧 | 前两名距离差 < 12px 时给 A/B 两个明确按钮，绝不自动替用户选 |
| 5.2 先预览再确认 | 摆位（村庄+道路整组）与建造都先进确认条，显示成本与缺口；取消只撤本地，并提示「服务器未发生变化」 |
| 5.3 收到更新复查选点 | `recheckPending()` 用 `candidateStillValid()` 复查，失效则清除预览、给出原因，不悄悄改选别处 |
| 5.3 动画与广播 | 相机容器（舞台 DOM，非 SVG 内层）与焦点稳定；见第 7 节的已知差距 |

## 4. 第 6 节流程入口对照

| 流程 | 本阶段实现 | 备注 |
|---|---|---|
| 入房 | 昵称/房间 → 等待 → 开局（沿用旧浮层） | 分享链接仍带 `name`/`room`，身份凭证另立任务 |
| 开局摆位 | 选村庄 → 选相邻道路 → **整组预览 → 确认** | 显示第几步/共几步；取消不改服务器 |
| 普通建造 | 选类型 → 成本/缺口 → 点合法位置 → **确认** | 确认后才发命令；收到 STATE 才更新资源 |
| 掷骰 | 点击 → 本地按压反馈 → 权威点数 → 产出高亮 | 不用动画随机数结算 |
| 结束回合 | **明确确认**，并给出不能结束的具体原因 | 未掷骰 / 强盗未处理 / 未轮到你 / 弃牌锁 / 未同步 |
| 查看发展卡 | 卡片列表 + 种类 + 可用状态 | 当回合购入不可用、胜利点不需打出 |
| 购买发展卡 | 成本预览 → 确认 → 私有卡面 | 不向他人展示买到的种类 |
| 骑士 | 棋盘选地块 → 选可偷玩家 / 不抽牌 → 提交 | 与掷 7 强盗待办互不覆盖 |
| 垄断 | 选资源种类 → 确认 | 不推算他人隐藏资源 |
| 丰饶 | 选两份资源 → 确认 | 允许两份相同 |
| 筑路 | 选 1–2 条路（可只提交一条）→ 确认 | 全程本地预览，确认前不扣资源 |
| 银行 / 自有港口 | 选交出 → 显示可见比例 → 选得到 → 确认 | 同种兑换禁用；比例提示以服务端裁决为准 |
| 借港代换 | 选受益人 / 交出 / 得到 → 确认 | 不请求对方隐藏手牌、不自动收租 |
| 对局结束 | 胜者、分数、结果摘要 | 「回到房间」只收起界面；重新开局服务端未支持，另立任务 |

## 5. 多报价展示、回合外报价与连接恢复（指南 7.4 / 8.3 / 10.1）

- 棋盘的 `#offer` 改成**只显示未处理数量**的常驻入口；列表/详情在侧抽屉，操作按钮位置固定，过期后当前详情变「已过期」并禁用原操作，不自动跳到下一条。
- 收件人视角转换由纯函数 `offerPerspective()` 实现并有单测；不会把发起人的「我给」当收件人的「我给」。
- 倒计时用 `snapshot.serverTime` 与本地 `Date.now()` 的差值估算；发送按钮显示冷却秒数，草稿在冷却期间仍可编辑，重发必须再次主动点击。
- **修复 P0**：`btnTrade` 不再因「不是自己的回合」而禁用，只受弃牌锁约束；报价对象按 `offerTargets()` 呈现（非当前玩家只能选当前玩家）。
- 连接状态区分：连接中 / 已同步可操作 / 中断恢复 / 无法恢复。`setSynced()` 只在拿到 WELCOME/STATE 后置真，WS OPEN 不算同步；离线时禁用会改变对局的操作并保留看盘与帮助。
- `GameClient.send()` 在非 OPEN 时触发 `onDrop` 给出可见反馈，**不排队重放**；提交后 8 秒内断线提示「正在核对结果，不会自动重发」；返回前台发 PING 探活并等待权威视图，不自动续期报价。
- 拒绝原因同时出现在操作附近的 toast 与底栏；触屏用「?」抽屉替代 hover 提示；减少动效开关保留静态高亮与文字；抽屉打开/关闭有焦点转移。

## 7. 已知差距（如实记录，不是已完成项）

1. **真机 / 浏览器运行时验证仍未做**：CDP 视口核对在阶段 B 被沙箱拦截（浏览器启动时删除自身临时文件），本阶段没有重试或提权。jsdom 冒烟只证明「DOM 齐、脚本能跑」，**不能证明画面与手势手感**；指南 12 阶段 D 要求的「一次完整多人对局验证」目前只做到真实 WS 协议级，浏览器里从入房到结束尚未跑过。
2. **SVG 内层仍整块重建**：`scene.ts` 每次 STATE `innerHTML` 重建地形/道路/建筑。相机与手势绑在稳定的舞台容器上，因此重绘不会打断双指操作、也不会重置镜头——这是整块重绘真正的危害所在；但指南 5.3 期望的「按 tile/edge/vertex 稳定 key 增量更新」尚未实现，留到阶段 E 性能采样后再做。
3. **港口比例是前端提示**：`portRatioHint()` 从公开的 `ports`/`buildings` 推导并明确标注「以服务端最终校验为准」，没有复用引擎的 `portRatioFor()`（前端只有 `PlayerView`，没有完整 `GameState`）。同种兑换禁用等硬规则仍由服务端裁决。
4. **结束界面没有重新开局**：服务端未支持重开，「回到房间」只收起界面并打开帮助；指南 6 明确要求另立任务。
5. **发布边界不变**：`release/` 仍是 15:22 的 v1 旧打包，与 v2 协议不兼容；本阶段未更新、未触碰线上房间（指南 14.9）。`pnpm build` 只更新 `apps/web/dist` 与 `apps/server/dist/public`。
6. 身份恢复凭证、房间持久化、公共分数信息公开规则（指南 10.3）仍未实施。
7. 阶段 B 的真机点选 / CDP 视口截图仍是未关闭的风险项（用户以「勉强合格」验收）。
