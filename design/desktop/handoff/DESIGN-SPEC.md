# 晴湾纸雕 · 桌面 UI 设计规范

> 阶段：视觉方向已选定 **B · 晴湾纸雕**。  
> 日期：2026-11-10。  
> 范围：桌面端 1280×720 及以上；独立设计原型，未修改正式游戏、引擎与规则。  
> 代码原型：`design/desktop/papercut.html`；五状态入口：`design/desktop/papercut-states.html`。  
> 本规范供其他 AI / 开发者实施；以原型文件为视觉事实来源，以下数值为交付口径。  
> **Round 2（2026-11-10）**：已按 `docs/20-papercut-refinement.md` 重做交易两步流程、报价切换、弃牌持有/已选、道路对比与轻量动效；详见 `handoff/REFINEMENT-ROUND2.md`。

## 0. 先读：实施边界

1. **不要重写引擎。** 正式游戏已有状态、合法性与服务端 truth；UI 只渲染 `PlayerView`、`offers`、`phase`、`BoardState` 等已有数据，不在前端另造规则。
2. **不要复制原型 HTML/CSS 整体。** 原型是设计草稿，含演示态、模拟计时和本地逻辑；正式实现应复用本规范与资产，而不是把 `design/desktop/` 当生产代码。
3. **不依赖颜色单一编码。** 玩家身份由颜色 + 建筑屋顶名字首字 + 道路中心线纹理共同表达；信息由图标 + 文本 + 颜色共同表达。
4. **棋盘只用 SVG / CSS 表达。** 地图、棋子、港口、数字片都是矢量；纹理只作底层，不把文字、数字、资源数量烘焙进图片。
5. **视口承诺。** 1440×900 为主设计视口，1280×720 为最低支持；1366×768 已检查。低于 1180px 只给提示，不承诺手机布局。
6. **原型中的模拟。** 报价倒计时、丙的弃牌、抽牌内容、结束回合切换都是本地演示；正式实现以服务端裁决与真实计时为准。

## 1. 方向决策

选择 **B · 晴湾纸雕**：

- 更像“朋友围在桌边的实体桌游”，而不是软件后台或深色数据面板。
- 手牌、报价、主按钮的对比与触感更直接，第一次打开就能读懂。
- 层叠纸片、丝网印海面、木块棋子能承载后续美术资产，同时不牺牲信息清晰度。
- A · 航海图志保留为对照历史（`compare.html`），不在本轮实施。

一句话气质：**晴湾桌面上的一盒纸雕岛屿游戏；暖、脆、厚、能按。**

---

## 2. 设计原则

1. **棋盘是主角。** 任何面板、浮层、提示都不能长期遮住岛；交易用右侧浮动面板，建造用棋盘高亮 + 右栏任务卡，弃牌用手牌区直接选。
2. **一个时刻只有一个主任务。** 右栏永远只有一张 task card 解释“现在做什么”；不要叠两张任务卡。
3. **实体感来自边缘与厚度。** 纸边 1.5–3px 深墨线、底部 2–4px 实色投影、圆角 9–16px；不用玻璃拟态、模糊背景、霓虹发光。
4. **颜色是气氛，不是唯一信息。** 地形有图标/插画/文字，玩家有名字首字与道路纹理，资源有图形与中文名，危险/成功有文案原因。
5. **强制流程不藏操作。** 弃牌、强盗、建造的确认与取消始终在可见区域；禁用按钮必须给出原因，而不是只变灰。
6. **信息密度像桌游，不像仪表盘。** 公开信息（分数、手牌数、发展卡数、最长路/最大军、港口）可见；隐藏信息（手牌内容、抽牌结果）绝不泄露。

## 3. 设计 token

### 3.1 颜色

原型 token 在 `design/desktop/css/papercut.css` 顶部；正式实现建议放入全局 `theme.css`。

| Token | 值 | 用途 |
|---|---|---|
| `--ink` | `#23372F` | 主文字、深色纸边、图标 |
| `--ink-soft` | `#4E6257` | 次级文字、说明 |
| `--muted` | `#5B6C60` | 辅助标签；小字实际使用 `#56685C` 以满足对比 |
| `--paper` | `#FFF6E2` | 卡片、面板底色 |
| `--paper-2` | `#F2E3C6` | 次级纸面、手柄底 |
| `--paper-deep` | `#E6D2AB` | 深纸边、底纹 |
| `--rule` | `rgba(35,55,47,.16)` | 分隔线、虚线圈 |
| `--accent` | `#E9A93B` | 主操作黄、太阳、港口、高亮 |
| `--accent-ink` | `#2B332B` | 黄底上的文字 |
| `--hot` | `#B84E37` | 危险/强制/计时文字；红色填充另用 `#D9654C` |
| `--ok` | `#3E7454` | 成功、完成、连接状态 |
| `--focus` | `#D9654C` | 键盘焦点环 |
| 玩家 A | `#C9503F` | 珊瑚红；甲 |
| 玩家 B | `#3B6FA0` | 海蓝；乙 |
| 玩家 C | `#B4741D` | 深赭黄；丙（和黄麦田拉开对比） |
| 玩家 D | `#4C8B67` | 叶绿；丁 |
| 纸边 | `#2A4036` | 面板/按钮/棋盘外框 |
| 奶油高光 | `#FFF3D8` | 纸片内高光、棋子描边 |
| 海面 | `#7AC8BF → #44A0A0 → #2B7E84 → #1D6971` | 径向海面 |
| 桌面 | `#3D9394 / #2A7C7D / #2A7A80 / #175A62 / #12484F` | 顶栏+底栏背后的径向桌面 |

用色规则：

- **黄色**：主操作、掷骰、太阳、港口、选中位置。
- **珊瑚红**：强制任务（弃牌/强盗）、危险、计时、负向变化；不要大面积铺满背景。
- **叶绿**：成功、完成、连接、正向变化。
- **海蓝/青色**：棋盘环境，不作为按钮主色。
- 玩家色只用于玩家相关对象（头像、屋顶、道路、棋子），不用于通用按钮。
- 地形底色是插画层，不承担 UI 语义；地形名/图标/数字必须独立可读。

对比：正文与重要小字目标 ≥ 4.5:1；大号数字（≥ 18.5px 粗体）目标 ≥ 3:1。原型已把 `#56685C` 用于 8–10px 标签，避免原来的 `#7B8D80` 对比不足。

### 3.2 字体

正式实现建议自托管：

- 中文 / 界面：**Noto Sans SC**（SIL OFL），400 / 500 / 600 / 700 / 800。
- 拉丁 / 数字：**Inter**（SIL OFL），400 / 600 / 700 / 800；使用 `font-variant-numeric: tabular-nums`。
- 原型在 macOS 上回退到 `PingFang SC` / `Avenir Next`；不要依赖系统字体作为唯一方案。

| 层级 | 1440 主视口 | 1280 紧凑 | 字重 | 说明 |
|---|---|---|---|---|
| 品牌名 | 20px | 17px | 700 | 顶栏左侧 |
| 玩家名 | 14px | 12.5px | 700 | 顶栏 chip |
| 玩家分数 | 21px | 19px | 800 | lining numerals |
| 任务标题 h2 | 22px | 18px | 800 | 一屏一行优先；标题不超过 12 字 |
| 任务正文 | 13px | 11.5px | 400 | line-height 1.68 / 1.58 |
| 报价名 | 11.5px | 10.8px | 600 | offer ticket |
| 倒计时 | 14px | 13px | 800 | 珊瑚红 |
| 资源名 | 10.5px | 9.5px | 700 | 手里卡片 |
| 资源数量 | 31px | 25px | 800 | 右下角 |
| 手牌总数 | 32px | 26px | 800 | 左下 |
| 按钮主 | 14.5px | 14px | 700 | 掷骰/发送/下一步/确认 |
| 按钮次 | 11.5px | 10.8px | 600 | 建造/交易/兑换；接受深绿 |
| eyebrow | 9.5px | 8.5px | 700 | letter-spacing .1–.14em |
| 日志 | 10.5px | 9.5px | 400 | 最多 3 行（紧凑 2 行） |

规则：

- 中文标题允许 1–2 行；任务标题超过 12 字时优先改文案，不要缩到 16px 以下。
- 不使用全大写中文；拉丁标签可用大写 + 字距。
- 数字统一 lining/tabular；时间、分数、资源数量右对齐。

### 3.3 形状、边线与阴影

- 棋盘外框：3px `#2A4036`，圆角 20px；内圈 2px 奶油半透明。
- 面板/任务卡：1.5px 深墨线，圆角 16px；底部 4px 实色投影 + 10–24px 柔和阴影。
- 报价票/资源卡：1.5–2px 墨线，圆角 11–13px。
- 按钮：圆角 10–12px；主按钮高 45px（紧凑 39px），次按钮 34–37px（紧凑 31px）；按下 `translateY(1px)`，投影缩短。
- 纸上高光：顶部 1px 奶油线，透明度 .35–.55；不要用大面积白色渐变。
- 禁止：玻璃模糊、背景 blur、内外发光描边、紫色渐变、3D 翻转。

### 3.4 间距与网格

- 基础步长 4px；常用 5 / 6 / 8 / 9 / 12 / 14 / 18 / 22。
- 卡片内边距：主视口 18–22px，紧凑 12–14px。
- 顶栏与主区之间不留额外缝；主区底部 gap = `--gap`。
- 右栏卡片间距：9px 主视口 / 6px 紧凑。
- 底部手牌架：左标签、手牌、发展卡、操作四组；gap 20px 主视口 / 13px 紧凑。

### 3.5 动效

| 动效 | 时长 | 曲线 | 说明 |
|---|---|---|---|
| 掷骰滚动 | 680ms | `cubic-bezier(.3,.7,.4,1)` | 两枚骰子轻微错峰；结果落定后再渲染状态 |
| 交易步骤/视图切换 | 180ms | ease | 面板位置不动，仅内容轻入；不重置草稿 |
| 数量变化 | 160ms | ease | 数字缩放脉冲；滑条/输入/加减同步 |
| 购买发展卡 | 380ms | `cubic-bezier(.22,.78,.32,1)` | 从牌堆飞向发展卡计数；不泄露牌面 |
| 强盗抽牌 | 460ms | 同上 | 手牌数先更新，再飞一张背面卡；不泄露资源种类 |
| 棋子/卡片按压 | 120ms | ease | translateY(1px) |
| 卡牌悬停 | 180ms | `cubic-bezier(.34,1.4,.64,1)` | 上浮 3px，仅桌面 hover |
| 抽屉进入 | 180ms | ease | 从右 10px + 淡入 |
| 浮层进入 | 140ms | ease | 5px + 轻微 scale |
| Toast | 3200ms | 停留 | 出现 160ms，退出 180ms |
| 建造/强盗高亮 | 1.9s 循环 | ease-in-out | 只做透明度呼吸；被选中后停止 |

`prefers-reduced-motion: reduce` 时全部缩短至 0.01ms，棋盘缩放无过渡。

### 4.2 1280×720（最低支持视口）与 1366×768

`@media (max-width: 1399px), (max-height: 819px)` 启用紧凑规格；1366×768 同样走紧凑规格：

| 区域 | 尺寸 |
|---|---|
| 顶栏 | 64px，padding 14px |
| 主区 | 534px；列 `minmax(0,1fr) 292px`，gap 14px，padding 14px |
| 棋盘外框 | 946×520px |
| 右栏 | 292×520px |
| 底栏 | 122px |
| 手牌卡 | 78px 高 |
| 发展卡堆 | 142×78px |
| 操作区 | 292–344px 宽 |

紧凑规格的取舍：

- 品牌 tagline 隐藏；玩家 chip 高度 46px、头像 24px；成就 badge 只留图标。
- 右栏第三行日志隐藏；底栏 meta inline 隐藏（完整内容在“岛上动静 → 全部”浮层）。
- 手牌/资源卡缩小；报价 accept 按钮高度 25px；抽屉宽度 408px。
- 不隐藏任何主操作；不出现页面级滚动。

低于 1180px：显示一条“建议在 1280×720 以上查看”的提示，不承诺完整布局。

### 4.3 区域职责

**顶栏**

- 左：六角 logo、品牌名、`HEX FRONTIER` 小标（紧凑隐藏）、房间/人数/连接状态。
- 中：玩家 chip 四个：头像、名字、分数、手牌数、发展卡数、成就 badge；当前玩家有黄色外圈与上浮 1px；手牌 ≥8 时手牌数变珊瑚红。
- 右：回合 `ROUND 14`、`甲行动中` 与阶段副标题（未掷骰/已掷骰/弃牌阶段/等待弃牌/强盗待放置/选择抽牌对象）、帮助按钮。

**棋盘**

- SVG `viewBox="0 0 1040 720"`，默认 `preserveAspectRatio` 居中；外框裁切。
- 岛为中心六边形拼图；海面为径向青绿 + 波纹；太阳在右上；帆船在右下；地形/港口/建筑/数字/强盗的层级顺序见 §6。
- 左下：棋盘事件 slip（骰子 + 结果 + 一句状态）；右下：缩放工具；悬停地块显示 tooltip（不遮挡数字）。
- 强盗：深绿纸雕 pawn；当前落点不参与产出（视觉上用 pawn 标记，数字不变灰；若产品要求可加小“停产”标签，不改变主视觉）。

**右栏**

- 顺序固定：当前任务卡 → 桌上提议 → 岛上动静。
- 同一时刻只有一张任务卡；交易抽屉打开时覆盖右栏，但板面保持可见。
- 右栏允许滚动，但 1440/1280 的三个主状态必须不滚动；强制流程（弃牌/强盗）在设计上也要在首屏可见确认按钮。

**底栏**

- 左：手牌标签（总数/风险或弃牌进度）。
- 中：5 张资源卡；每张显示地形色顶条、资源图标、中文名、数量、港口标签（如 2:1）。
- 右：发展卡堆；发展卡数量、可打提示；强盗/弃牌阶段锁定并显示原因。
- 最右：主动作（掷骰或确认弃牌）、次动作行（建造/交易/兑换/结束回合）、一行原因说明。
- “结束回合”优先使用弱按钮；未掷骰/强盗未结算时禁用并给出文字原因。

### 4.4 层级

`顶栏 30 > 底栏 25 > 棋盘内容 1–6 > 抽屉 70 > 浮层 80 > Toast 90 > 小窗口提示 200`。抽屉/浮层不使用全屏暗遮罩；点击棋盘可继续操作，但交易面板打开时点击空白只关闭浮层，不关闭抽屉。

## 5. 组件

### 5.1 玩家 chip

- 尺寸：236×52px（紧凑 220×46px），最多四个；flex 均分。
- 内容：27px 圆角方头像（玩家色 + 名字首字，奶白文字 + 1px 暗描边）、名字、`手牌` 图标 + 数字、`发展卡` 图标 + 数字、成就 pill。
- 当前玩家：黄色外圈 2px + 上浮 1px；不是只改文字颜色。
- 手牌 ≥8：手牌数字珊瑚红，risk-tag 出现。
- 成就 pill：`最长路 乙 · 8` / `最大军 丁 · 3`；紧凑只留图标 + 数，完整信息在玩家详情。
- 点击打开玩家详情：分数、成就、建筑数、手牌数（内容不可见）、发展卡数（未公开）、港口、已打出骑士；关闭按钮 32px。

### 5.2 任务卡（task card）

- 宽 324/292px；背景奶油纸；顶部 7px 三色条（珊瑚/黄/绿）；珊瑚/黄/绿分别对应行动/等待/成功等语境。
- 右上圆形“图章”：当前玩家名字首字；特殊状态替换为 `7` / `路` / `村` / `盗` / `抽`；纸雕风格为深墨描边 + 4° 旋转。
- eyebrow：脉冲点 + 阶段名 + 回合；h2 一行优先；正文最多 2–3 行；risk chip 一行；底部 foot 一行“当前阶段/资源足够/仍锁定”。
- 变体：
  - 未掷骰：`你的回合，尚未掷骰`；短提示“先掷骰，或先建造 / 交易”。
  - 已掷骰：`骰子已落，继续行动`；提示可建造/交易/打 1 张发展卡。
  - 建造：`放置一条道路/一座村庄`；费用、步骤、确认/取消。
  - 弃牌：`你需要弃掉 N 张`；进度条、已选/需求、其他玩家等待。
  - 等待：`你已弃 N 张`；玩家等待列表。
  - 强盗：`把强盗移到哪里？`；规则、恢复/锁定说明。
  - 抽牌：`从谁手里抽 1 张？`；相邻玩家按钮、手牌数。
- 任务卡绝不叠放；如果建造/交易临时占用，强盗待完成用一条 `pending-chip` 留在顶部。

### 5.3 报价卡（offer ticket）

- 每条：珊瑚色玩家头像、`丙 的提议`、大号倒计时；统一从玩家视角显示 **你给出 → 你收到**，大号数量；接受（深绿）/拒绝（纸白）。
- 倒计时条：底部 2–3px，珊瑚红；10 秒总长。
- 接受前以对局 truth 复核资源；不预占；失败提示并保留/刷新。
- 空状态：`暂时没有待处理提议。需要换资源时，可以直接发起一笔。` + `发起交易` 文本按钮。
- 7 点清空：珊瑚左边条 + `已清空` 小标 + 锁定文案；弃牌完成前不显示发起交易。
- 紧凑：报价名 10.8px、倒计时 13px、接受按钮 26px（深绿，11px）。

### 5.4 资源卡（手牌）

- 尺寸 96/78px 高；2px 墨边，13px 圆角，顶部 8px 地形色条；34/26px 图标底纸；左下中文名，右下大数字；港口标签在右上。
- 空资源：灰度 55% + 透明度 .55；不隐藏，保持牌位稳定。
- 悬停上浮 3px；点击打开资源详情（本地图/港口/用途）。
- 弃牌模式：
  - 卡片可点击；数字上方小标 `持有`，顶部中央珊瑚 `已选 N −` 徽章；点击徽章取消 1 张。
  - 选中卡片 3px 珊瑚外圈 + 上浮；总进度 `3/5` 在手牌标签和确认按钮；港口标签在弃牌时隐藏。
  - 选满后确认按钮由黄变珊瑚实心；未满禁用。
- 生产实现要求：把“增加选择”和“取消一张”拆成两个真正可聚焦的按钮，避免原型中嵌套 span 的键盘缺口。

### 5.5 发展卡堆

- 166×96 / 142×78px；三张错位纸卡扇形；显示数量、`本回合可打 1 张`。
- 锁定态：虚线边框、透明度 .66、说明 `弃牌阶段锁定` / `强盗结算后可打`；按钮 disabled。
- 点击打开发展卡详情；未公开内容不泄露；正面卡牌清单见资产表。

### 5.6 按钮与操作

- 主按钮（黄色）：掷骰、发送、下一步、确认弃牌；高 45/39px，字号 14–15px，左侧图标，右侧 `2d6`/数量。
- 接受报价：深绿实心（`#2A4036`），不与金色主操作争抢；拒绝纸白。
- 次按钮：建造/交易/兑换 34–37/31px；四列等宽；结束回合弱化、右对齐。
- 强制动作：弃牌确认（珊瑚）；等待中使用禁用虚线主按钮。
- 禁用必须同时有原因文案（按钮 title + `action-note`），不能只降透明度。
- 点击目标桌面最小 28×28px；主按钮 39px 高；避免悬停才出现的关键操作。

### 5.7 交易抽屉（两步图形选择）

- 右浮动面板：438/408px 宽；顶部 `top-h+8`，底部 `shelf-h+10`；纸面 + 2px 墨边 + 16px 圆角；不用全屏暗遮罩。
- 顶部固定：标题 `和 X 换资源`、交易对象 chip（含手牌数）、`发起交易 / 收到的提议 (N)` 分段切换。
- 发起交易分两步：
  1. **我想收到**：五行动态资源行，图标 + 名称 + 大号整数 + 滑条 + 减/加；数量可直接输入，滑条 max 随输入扩展；不显示对方持有量。
  2. **我愿给出**：同样行，显示 `持有 N`，上限按自己当前资源；零资源仍保留位置但不可增加；顶部保留第一步摘要和“修改”。
- 底部：第一步显示 `收到：…` + `下一步：我愿给出`；第二步显示完整条件 `给 X：… → 收到：…`（或仅赠予/向…索取）+ `发送给 X`；不再叠第三层确认。
- 草稿：切换步骤/对象/报价 tab/关闭再打开均保留；7 点、阶段变化、权限变化时校正/清空，不自动发送；给出侧超过持有标红并禁用。
- 发送中禁用防重复；成功显示“已向 X 发出提议 + 完整条件 + 剩余秒数/冷却 + 撤回”；10 秒后本地过期，3 秒冷却结束后“再发一笔”恢复。
- 交易规则：每人同时 1 条活跃报价；10 秒有效；发送后 3 秒冷却；被报价方可接受/拒绝；成交瞬间转移，撤回即失效；不预占资源。
- 收到的提议列表：从玩家视角显示 `你给出 / 你收到`；按到达顺序稳定排列；按 offerId 接受；过期移除；新报价只更新数量/轻提示，不切 tab、不抢焦点、不重绘编辑中的输入。
- 错误：资源不足/冷却中/对象已离线，用面板内红色提示 + toast，不关闭面板。
- 紧凑：抽屉 408×516；五资源行约 40px；步骤说明在紧凑下隐藏，保留标题、数量、摘要、条件、发送。

### 5.8 抽屉之外的浮层

- 玩家/资源/发展卡/帮助/日志：宽 332/312px（玩家详情可略宽）；锚点上方或下方；点击外部/Esc 关闭；不遮手牌；不嵌套滚动。
- 日志浮层：完整 4 条 + 底栏 meta（牌堆/最长路/最大军）。
- 帮助：最短规则、图标说明、原型边界；不超过 6 行。
- Toast：底部居中，深墨底、奶白字、18px 图标；默认 3.2 秒；错误/强制用珊瑚左条；不覆盖主按钮。

### 5.9 棋盘事件 slip 与 tooltip

- 事件 slip：左下 18px；两枚 26px 骰子 + `甲 掷出 7 点` + 副行；纸白 + 墨边 + 2px 底投影；10° 内轻微旋转；进入 420ms。
- hover tooltip：地块名、点数、产出、是否被强盗占据；不遮挡数字；`pointer-events:none`；建造/强盗选点模式隐藏。
- 缩放：+ / − / ↺；范围 0.88–1.4；重置 1；以 520,360 为 transform-origin。

### 5.10 建造与强盗高亮

- 建造边：墨色底 7.5px + 奶油 9px + 黄虚线 4.6px + 中点徽章 `+`；选中后黄实线 6.2 + `✓` 徽章。
- 建造点：奶油圆 + 黄环 + `+`；选中后 `✓`。
- 强盗：合法地块 94% 缩放虚线六边形 + 右上金色地图钉；当前强盗地块不出现；点击后立即落子并进入抽牌对象。
- 命中层始终大于视觉线宽（边 22px、点 28px、地块整块），避免点不中。
- 确认/取消在右栏任务卡，不在棋盘上叠一条大工具条。

## 6. 状态与流程

### 6.1 普通对局（初始）

- 第 14 回合，甲行动；甲手牌 9，乙 6，丙 9，丁 7；两条待处理报价；强盗在北岸 6 号田；甲 8 分、最长路乙 8、最大军丁 3。
- 甲未掷骰；四个报价/建造/发展卡/结束回合的可用性按规则；结束回合禁用，原因 `需先掷骰`。
- 掷骰：两枚骰子 680ms；结果落定后更新：
  - 非 7：按点数产出资源，事件 slip 更新，手牌与风险更新；进入已掷骰行动阶段。
  - 7：**报价全部清空**，进入弃牌/强盗流程；不产出资源。
- 已掷骰：建造/交易/兑换/发展卡可用；结束回合可用；主按钮变 `本轮已掷骰` 禁用。

### 6.2 交易状态

1. 当前玩家可向其他任意玩家发起；非当前玩家只能向当前玩家发起；每人同时 1 条活跃报价，全桌可多条并存。
2. 顶部对象始终可见；切换对象保留草稿，但重新检查权限与可发送性。
3. **第一步 我想收到**：五种资源均可选、可为 0；数量/滑条/加减同步；进入下一步不丢草稿。
4. **第二步 我愿给出**：给出上限按当前持有；显示 `持有 N`；零资源不可增加；底部完整条件；发送不再弹确认。
5. 发送：服务端校验资源与冷却；成功后报价进入对方列表，10 秒倒计时；发送方 3 秒冷却；发送中防重复；失败保留草稿并给出原因。
6. 被报价方接受：服务端复核双方资源；成交瞬间转移；报价移除并写日志；失败则保留/刷新并提示原因。
7. 拒绝/过期/撤回：只移除报价，不转移资源；过期 offerId 拒绝接受。
8. 编辑期间收到报价：只更新 `收到的提议 (N)` 和轻提示，不抢焦点；切换 tab 保留草稿；报价列表从玩家视角展示你给出/你收到。
9. 7 点：所有活跃报价立即失效；关闭交易抽屉并清空草稿，进入弃牌阶段。
10. 原型模拟：倒计时只在交易面板打开时推进；发送成功/冷却/过期是本地演示，不宣称正式多人已接入。

### 6.3 弃牌与强盗（核心流程之一）

触发：掷出 7 或规则层进入 `seven`。

**阶段 A：弃牌**

1. 清空所有 offer；log 写 `甲 掷出 7 点 · 所有报价作废`；右栏任务卡切为弃牌卡；报价卡变“已清空”。
2. 计算每个玩家需求：手牌 ≥8 时 `ceil(手牌/2)`；甲 9→5，丙 9→5，乙/丁 6/7→0。
3. 当前玩家直接在手牌区选牌：
   - 手牌卡可点击；每张牌显示 `持有 N`；顶部 `已选 N −` 徽章取消 1 张；已选/需求实时显示；未满时确认禁用。
   - 底栏操作替换为 `确认弃牌 N/N` + `重选`；建造/交易/兑换/发展卡全部暂停。
4. 确认：扣除所选资源；写日志 `甲 弃掉 N 张（内容不公开）`；进入等待。
5. 其他需弃牌玩家显示等待列表（头像 + 名字 + 需求/状态）；正式实现由服务端接收他们自己的选择；原型 1.05s 模拟丙弃 5 张。
6. 所有弃牌完成后：建造/交易/兑换恢复；发展卡与结束回合保持锁定；进入阶段 B。

**阶段 B：强盗**

1. 右栏 `把强盗移到哪里？`；棋盘所有**非当前强盗地块**出现虚线 + 金色地图钉。
2. 点选地块：强盗 pawn 落到该地块；计算相邻建筑拥有者（排除自己）。
3. 若有相邻其他玩家：切 `从谁手里抽 1 张？`，列出玩家 + 手牌数；选择后该玩家手牌 -1，抽到什么不公开；写日志 `甲 把强盗移到森林 12 号，从丙抽走 1 张`。
4. 若无相邻其他玩家：直接结算 `相邻没有其他玩家`。
5. 结算后：清除 seven 状态；恢复已掷骰行动阶段；结束回合可用；报价仍为空；发展卡恢复（若未使用）。
6. 弃牌完成但强盗未选时，建造/交易/兑换可用；若用户切去建造/交易，右栏顶部保留 `强盗待放置 · 继续` chip；返回后继续选点。发展卡、结束回合仍锁定。

**边界**

- 无人需要弃牌：直接进入强盗。
- 当前玩家无需弃牌、但他人需要：显示等待，不能先移强盗。
- 多个玩家需弃牌：等待列表逐个显示；服务端按玩家提交推进，超时按规则自动弃（具体策略由产品定）。
- 强盗地块没有其他玩家建筑：不出现抽牌卡。
- 目标玩家手牌为 0：抽牌结果 0，日志明确写 `无牌可抽`；不显示虚假 -1。
- 断线重连：以服务端 `phase=seven/discard/robber` 与 `discardRequired` 恢复；不要依赖前端计时。
- 动画/防连点：确认后立即锁按钮，服务端确认前显示 submitting；失败回滚并提示。

### 6.4 建造（支持流程）

- 点击建造 → 选择道路/村庄；右栏任务卡解释合法条件与费用；棋盘出现金色 `+` 边/点。
- 选择位置 → 选中态 `✓`；确认按钮在右栏；Esc/取消退出。
- 确认：服务端校验资源、连通、空位；成功后扣费、落子、写日志；失败提示具体原因。
- 城市升级在正式实现中同流程扩展；原型因矿石不足仅保留入口。

### 6.5 结束回合

- 未掷骰/强盗未结算：禁用 + 原因。
- 已掷骰：允许；确认浮层 `确认结束？` → 服务端推进；成功后下一家、回合号/阶段更新；失败提示。
- 不自动结束；不跳过弃牌/强盗。

## 8. 无障碍

### 8.1 对比

已核对（背景为主纸面 `#FFF6E2`）：

| 前景 | 比率 | 用途 |
|---|---|---|
| `#23372F` | 11.77 | 主文字 |
| `#4E6257` | 6.09 | 次级 |
| `#56685C` | 5.53 | 小标签（实际使用） |
| `#B84E37` | 4.67 | 倒计时/危险文字 |
| `#3E7454` | 5.10 | 成功 |
| `#A9402C` on `#FFE8DD` | ≥4.5 | 风险 tag |
| `#2B332B` on `#F2C15B` | 7.79 | 黄色图章 |

- 8–10px 小字不低于 4.5；大号数字 ≥3。
- 资源/地形不只靠颜色：图标 + 中文名 + 数字；玩家建筑有屋顶名字首字；道路有不同虚线中心线；玩家 chip 有名字与头像。
- 禁用按钮的说明文字仍保持可读；禁用控件本身可降低透明度。

### 8.2 键盘与焦点

- 焦点环：2px 珊瑚红 + 2px offset；所有按钮/链接可见。
- 交易抽屉打开：焦点进入面板，Tab 循环，Esc 关闭并返回触发按钮；`role=dialog aria-modal=false` 或侧栏模式按实现定。
- 浮层：Esc 关闭，焦点返回锚点。
- 建造/强盗 SVG 热区必须可 Tab：生产实现使用真正的 `<button>`/可聚焦元素，带 `aria-label` 与序号；原型目前是 SVG g + role=button 的视觉演示，键盘导航待补。
- 弃牌选择：生产实现把“卡片增加”和“徽章减少”拆成两个按钮（或卡片 + 独立步进器），避免嵌套交互。
- 进度/阶段变化用 `aria-live="polite"`：`已选 3/5`、`等待丙弃牌`、`强盗待放置`、`已从丙抽 1 张`。
- 焦点不被 toast 抢走；模态/侧栏外内容设为 inert。

### 8.3 其他

- 支持 200% 缩放到 1280 宽的阅读：不裁切手牌/确认按钮；必要时允许右栏滚动。
- 悬停只作为补充，不作为唯一信息；地块详情在点击/焦点时也可得。
- 颜色弱视/色盲：玩家名字首字与道路纹理提供第二通道；不要给红绿玩家仅用颜色区分的关键按钮。
- 动效可关闭；骰子结果同时以文字呈现。
- 触控目标：桌面最小 28px，主操作 39–45px；若未来支持触控，提升到 40–44px。

## 9. 实施映射

### 9.1 数据契约（只读示例）

| 字段 | 用途 |
|---|---|
| `players[i].{id,name,color,score,handCount,devCount,knights,ports,buildings}` | 顶栏、玩家详情、成就 |
| `state.current`, `state.round`, `state.hasRolled` | 回合/阶段 |
| `state.hand[{key,count,port}]` | 手牌、弃牌选择 |
| `state.offers[{id,from,to?,give,want,seconds,total}]` | 报价列表 |
| `state.meta.{deck,longestRoad,largestArmy}` | 日志底栏/浮层 |
| `state.tiles[{key,terrain,number,u,row}]`, `state.robberTile` | 棋盘 |
| `state.buildings/roads` | 棋子/道路 |
| `state.phase` / `state.seven` | `normal` / `discard` / `waiting` / `robber` / `victim`；正式以服务端字段为准 |
| `state.discardRequired`, `state.discardSelected` | 弃牌进度 |
| `state.lastRoll{d1,d2,total,by,sub}` | 棋盘事件 |

前端只消费服务端 truth；弃牌选择、建造确认、报价接受都必须等待服务端 ack，不在本地先改最终状态。

### 9.2 建议结构

```text
src/ui/
  shell/           顶栏、布局、响应式
  board/           SVG 棋盘、地形、港口、棋子、数字、高亮
  hand/            资源卡、弃牌选择、发展卡堆
  actions/         掷骰、建造、交易、兑换、结束
  rail/            任务卡、报价卡、日志
  overlays/        交易抽屉、玩家/资源/帮助/日志浮层
  state/           UI 派生状态、选择/提交状态
  tokens/          CSS 变量、字体、纹理
```

- 不要改 `engine/`、规则、发牌、合法边/点算法；复用已有 `(u,row)` 几何与 key。
- 棋盘：`viewBox 0 0 1040 720`；`HEX_SIZE=56` 的几何与点/边 key 与原型一致。
- 渲染层：SVG 分 `<g data-layer="tiles|decor|ports|roads|buildings|robber|numbers|overlay">`；数字片必须在插画之上，overlay 在数字之上。
- 交互层：事件委托到 `[data-act]`；建造/强盗用 `data-edge` / `data-vertex` / `data-tile`。
- CSS：主题变量放在 `body[data-theme=papercut]`；组件只消费变量，不在组件内写死颜色。
- 纹理：纸张用低对比 tiling PNG/WebP（≤30% 透明），海面用 SVG pattern；不要用大尺寸背景图。
- 性能：19 地块 + ~30 建筑/道路 + 图标，纯 SVG 足够；避免每帧重绘大 filter；动画只改 transform/opacity。

### 9.3 实施顺序

1. 全局 token + 字体 + 纸张/海面纹理。
2. Shell 布局 + 顶栏 chip + 底栏骨架。
3. 棋盘地形/港口/数字/棋子/事件 slip（先静态）。
4. 手牌/发展卡/操作区 + 掷骰 + 风险。
5. 报价卡 + 交易抽屉 + 空/错误态。
6. 弃牌选择 + 等待 + 强盗地块/抽牌对象。
7. 建造高亮 + 确认/取消 + 资源校验。
8. 无障碍：焦点顺序、aria-live、键盘热区、对比复核。

### 9.4 验收清单

**布局**
- [ ] 1440×900 与 1280×720 无页面滚动；手牌、主按钮、当前任务卡完整可见。
- [ ] 右栏只有一张任务卡；报价/日志顺序固定；紧凑下隐藏第三行日志与 meta inline，但“全部”浮层可取回。
- [ ] 抽屉/浮层不遮手牌主操作；不出现全屏暗遮罩。

**普通**
- [ ] 顶栏四名玩家分数/手牌/发展卡/成就正确；当前玩家高亮；手牌≥8 变红。
- [ ] 掷骰动画结束后手牌/事件/风险同步；未掷骰时结束回合禁用且原因可见。
- [ ] 掷出 7 清空报价并进入弃牌；非 7 不误清。

**交易**
- [ ] 选对象/加减/净变化/发送完整；0 张允许，双方 0 时禁用。
- [ ] 接受前复核资源；失败不转移、不清报价。
- [ ] 10 秒/3 秒/一人一报价按服务端 truth；7 点全部失效。

**弃牌与强盗**
- [ ] 需求 = 手牌≥8 时 ceil(手牌/2)；当前玩家可点选/取消，满 N 才可确认。
- [ ] 确认后扣除所选；等待其他玩家；全部弃完才进入强盗。
- [ ] 强盗合法地块排除当前地块；相邻有建筑才出现抽牌对象；无牌可抽不显示 -1。
- [ ] 弃牌阶段建造/交易/兑换/发展卡全锁定；弃完但未结算时建造/交易/兑换恢复，发展卡/结束回合仍锁定。
- [ ] 强盗结算后结束回合恢复；日志/手牌数/事件副行同步。
- [ ] 断线重连按服务端 phase 恢复，不依赖本地定时器。

**无障碍**
- [ ] 文字对比 ≥4.5；玩家颜色有名字首字/道路纹理第二通道。
- [ ] 所有关键操作可 Tab/Enter/Space；焦点环可见；Esc 关闭浮层并返回锚点。
- [ ] 阶段/进度 aria-live；toast 不抢焦点。
- [ ] `prefers-reduced-motion` 下动画关闭。
