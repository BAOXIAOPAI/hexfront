# 晴湾纸雕 · 第二轮优化改动与测试记录

> 日期：2026-11-10。  
> 任务书：`docs/20-papercut-refinement.md`。  
> 范围：只修改 `design/desktop/` 内的独立原型与交付说明；未改 `apps/`、`packages/`、正式协议或规则，不部署。  
> 视觉方向保持 **B · 晴湾纸雕**，不重选风格。

## 1. 本轮改动

### 1.1 交易重做为两步图形选择

- 旧版：左右双栏共 10 行加减控件，密集且像表单。
- 新版：
  1. **我想收到**：五种资源固定排列，图标 + 名称 + 醒目整数 + 滑条 + 加减。
  2. **我愿给出**：同样结构，显示“持有 N”，上限按自己当前资源；零资源保持位置且不可增加。
  3. 第二步顶部保留第一步摘要与“修改”，底部显示完整条件并直接发送，不再弹第三层确认。
- 滑条支持拖动、点按加减和直接输入数字；数字输入不设任意业务上限，滑条 max 随数字扩展；给出侧超过持有会标红并阻止发送。
- 允许任一侧为零：`仅赠予` / `向…索取`；双方为零禁用并显示“至少选择一种资源”。
- 顶部交易对象常驻；切换对象保留草稿；关闭再打开保留草稿与步骤；7 点、阶段变化时清空草稿，避免自动发送。
- 发送中禁用按钮；成功显示“已向 X 发出提议 + 完整条件 + 倒计时/冷却 + 撤回”；10 秒后本地过期，3 秒冷却结束后可再发。
- 权限、offerId、10 秒、3 秒、每人一条、多条并存等规则保留在交互与说明中；原型不接服务端。

### 1.2 收到的提议可见、可切换

- 交易面板顶部新增 **发起交易 / 收到的提议 (N)** 切换。
- 新报价到达时只更新数量、加轻提示和未读点，不切 tab、不抢焦点、不重绘编辑中的输入。
- 报价卡统一从玩家视角显示 **你给出 / 你收到**；接受按钮改为深绿，避免与金色掷骰/发送争主次。
- 打开交易面板时模拟报价倒计时（每秒推进，到期移除）；过期报价不能接受。
- 面板关闭后计时暂停；这是本地模拟，不代表正式多人计时。

### 1.3 可读性、层级、弃牌和道路

- 主要操作字号提升到 14–15px；报价名、资源数量、关键状态、按钮文字上调；不靠缩小字体硬塞。
- 深绿“接受” / 金黄“掷骰、发送、确认弃牌”：同一视图只保留一个金色主操作；次要动作用纸白或深绿。
- 弃牌卡：
  - 每张牌显示“持有 N”（数字上方小标）和“已选 N −”徽章；
  - 徽章可直接点击取消 1 张；手牌标签显示已选/应弃；
  - 隐藏弃牌时的港口小标签，减少干扰。
- 黄色玩家 C 从 `#D99A35` 改为更深的赭黄 `#B4741D`；道路加粗奶油/墨线描边，中心虚线保留；建筑屋顶仍带玩家名字首字。
- 常态任务卡改为短句，去掉“8 张起弃一半”等长教程；规则留在帮助。技术用语“服务端复核”改为玩家能理解的结果说明。
- 交易里不再常驻“任意比例、报价 10 秒……”等大段规则；只保留必要即时提示。

### 1.4 动效

全部为 CSS / Web Animations，无 3D 或物理引擎：

- 骰子短翻滚：680ms，结果落定后更新状态。
- 交易步骤切换：180ms 轻入；面板位置不跳。
- 按钮按下、卡牌选择、数量变化：100–180ms 反馈；数量变化有缩放脉冲。
- 抽发展卡：新增长按“抽一张”入口（1 羊 + 1 麦 + 1 矿，标准费用），从牌堆飞向发展卡计数；不泄露给对手。
- 强盗抽牌：选择受害者后，先结算手牌与日志，再播放背面卡从受害者头像飞向自家手牌标签；不泄露资源种类。
- 减少动态模式：`prefers-reduced-motion` 下关闭飞行动画与过渡；抽牌直接显示结果。

> 说明：购买发展卡是原型新增的可点击演示动作，不改变本轮的三种核心状态；不是新增“交易卡”玩法。

## 3. 测试记录

### 3.1 尺寸与布局

在 Chrome 实测：

- **1440×900**：普通、交易第一步、第二步、收到的提议、弃牌、强盗均无整页滚动；交易抽屉 `scrollHeight = clientHeight = 654`，内容不裁切。
- **1280×720**：同样五类状态无整页滚动；抽屉 `512/512`，交易两步、提议、弃牌均可见；底部手牌/主按钮不被遮挡。
- **1366×768**：再检查，抽屉 `560/560`，无溢出。
- 普通对局右栏与底栏：1440 `658/658`、`143/143`；1280 `520/520`、`119/119`。

### 3.2 交易行为

| 用例 | 结果 |
|---|---|
| 混合资源（收 2 羊 1 矿；给 2 木 1 砖 1 羊） | 条件/发送正确 |
| 返回第一步 | 数量保留 |
| 切换对象 丙 → 乙 | 草稿保留，标题/对象更新 |
| 关闭交易再打开 | 步骤与数量保留 |
| 仅赠予（收到全 0、给出 1） | 显示“仅赠予”，可发送 |
| 仅索取（给出全 0、收到 2 羊 1 矿） | 显示“向…索取”，可发送 |
| 双方全 0 | 禁用，提示“至少选择一种资源” |
| 给出超过持有 | 标红“你只有 2 张木材”，发送禁用 |
| 收到数量输入 50 | 数字保留 50，滑条 max 自动扩到 50 |
| 滑条/加减/数字 | 三种输入同步，整数；摘要同步 |
| 新报价到达（编辑中） | 数量 +1、未读点/轻提示；焦点仍在数字输入，草稿不变 |
| 报价倒计时 | 每秒推进，到期从列表和右栏移除；过期点击被拒绝 |
| 切换“收到的提议” | 报价按 offerId 接受；数量更新；草稿保留 |
| 发送成功 | 显示完整条件、倒计时、冷却、撤回；3 秒后“再发一笔”恢复 |
| 撤回 | 成功卡消失，回到可编辑状态 |

### 3.3 弃牌/强盗/动效

- 弃牌：`?state=robber` 预选 3/5；每张牌显示持有；点击“已选 1 −”可取消；选满 5 后确认启用。
- 强盗：选地块 → 选受害者；手牌数先更新，再播放背面卡；普通模式 `.draw-fly` 出现后移除，减少动态模式不出现。
- 发展卡：购买后手牌 9→6、发展卡 3→4、日志和不泄露提示正确；抽牌 `.draw-fly` 播放。
- 骰子：B 版演示 7 点，680ms 后进入弃牌；未掷骰/强盗未完成时结束回合仍正确禁用。
- 控制台：上述流程 0 个 pageerror / console error。
- A 历史页：交易抽屉仍可打开与进入第二步，未出现 JS 错误；不做视觉承诺。

## 4. 仍未实现 / 本地模拟

- 无服务端：发送成功、对方接受、报价过期、丙弃牌、抽牌内容均为本地演示。
- 报价计时只在交易面板打开时推进；关闭后暂停；不代表正式计时。
- 结束回合只确认，不切换下一位；无完整终局。
- 断线/重连快照、权限变化后的草稿校正未在原型中模拟；设计规范列为正式实现要求。
- 无手机/平板布局承诺；仅桌面 1280+。
- SVG 边/点/地块热区与弃牌徽章的完整键盘导航仍待正式实现；原型已有按钮/滑块键盘路径。
- 字体仍使用 macOS 回退；生产需 Noto Sans SC + Inter。
